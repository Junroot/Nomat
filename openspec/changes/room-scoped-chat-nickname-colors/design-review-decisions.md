## Decision 5의 hex 표가 생성 파라미터·간격 주장과 다르고, 스펙의 "앞 8개 45° 이상"은 18° 격자에서 불가능
- 심각도: [높음]
- 질문 요지: 팔레트 표를 규칙대로 재생성하고 수치를 달성 가능한 값으로 낮출지, 규칙을 바꿔 45°를 지킬지, 표를 두고 주장만 실측으로 낮출지
- 사용자 결정: "규칙 유지, 표 재생성 + 수치 36°로". 추가로 재생성한 미리보기를 보고 밝기를 **L 0.77**로 재확정(이전 0.74는 변환 오류가 있는 미리보기 기준이었음)
- 반영 방향:
  - 원인 사실: 기존 표는 OKLCH→sRGB 변환 행렬의 오타(LMS→선형 RGB의 G 행 셋째 계수)로 잘못 생성된 값이었다. 설계에는 "표를 재생성했다"는 사실만 적고 오타 경위는 적지 않아도 된다.
  - 생성 규칙(design.md Decision 5 서술을 이렇게 교체): 색상환을 18°씩 20등분(시작 211.5° = 기존 neon-cyan 색상). **짝수 격자점 10개(36° 등간격)를 먼저** 거리순(이미 배정된 색과 가장 먼 것을 다음에 고르는 탐욕)으로 슬롯 0~9에 배치하고, **홀수 격자점 10개를 그 다음** 같은 탐욕으로 슬롯 10~19에 배치한다. OKLCH L 0.77, C 0.16 고정, sRGB 밖이면 채도만 깎는다. 결과: 슬롯 0~9는 서로 36° 이상, 슬롯 10부터는 이웃과 18°.
  - design.md Decision 5의 표를 아래로 교체하고, 다이어그램·본문의 "앞 8개 45° / 9~10명 22.5° / 11명+ 18°" 를 "앞 10개(슬롯 0~9) 36° 이상 / 슬롯 10부터 18°"로, "대비 전부 10:1 이상"을 "대비 전부 8.8:1 이상(WCAG 7:1 만족)"으로, "밝기 0.74"를 "0.77"로(세 후보 0.74/0.77/0.80을 올바른 변환의 미리보기로 비교해 고른 값) 고친다. 색상 이름(청록/살구 등)이 있는 곳은 새 슬롯 순서에 맞춰 다시 붙인다.
  - Goals의 "평균 인원 방에서는 항상 구분이 확실한 색" → "평균 인원(8명) 방은 슬롯 0~7만 쓰므로 서로 36° 이상 떨어진 색만 쓰인다"로 재서술. Risks의 "앞 10명까지는 22.5° 이상" → "앞 10명까지는 36° 이상".
  - specs/room-chat-nickname-color/spec.md: "앞 8개 슬롯은 서로 45° 이상, 앞 10개는 22.5° 이상" SHALL → "앞 10개 슬롯(0~9)은 서로 36° 이상, 슬롯 10부터는 이웃과 18°". 시나리오 "8명 이하 … 45° 이상" → "10명 이하 … 36° 이상". 대비 7:1 기준은 그대로 둔다(전부 만족).
  - proposal.md What Changes의 팔레트 항목: "평균 인원인 8명까지는 서로 45° 이상 떨어진 색만 쓰이고, 11명 이상인 드문 방에서만" → "10명까지는 서로 36° 이상 떨어진 색만 쓰이고, 11명 이상인 드문 방에서만".
