## Why

방 채팅에서 **서로 다른 참가자가 같은 닉네임 색**을 받는 일이 빈번하다. 두 사람이 번갈아 말하면 어느 줄이 누구의 말인지 색으로 구분되지 않아, 정답 추측이 오가는 게임 중 채팅의 가독성이 떨어진다. 아바타가 전원 같은 기본 아이콘이라 화자를 구분하는 시각 신호는 닉네임 색 하나뿐인데, 그 신호가 겹치면 구분 수단이 없어진다.

원인은 `ChatMessageList`의 색 선택 규칙이다. **전역 플레이어 id를 4로 나눈 나머지**로 네온 4색 중 하나를 고르기 때문에, 같은 방에 있는 사람들끼리 색이 다르다는 보장이 어디에도 없다.

| 방 인원 | 누군가 색이 겹칠 확률 |
|---|---|
| 2명 | 25% |
| 3명 | 62.5% |
| 4명 | 90.6% |
| 5명 이상 | 100% |

방 정원이 최대 20명이고 평균 8명 정도이므로 사실상 **모든 방에서 겹친다.** 팔레트를 늘리는 것만으로는 확률이 줄 뿐 없어지지 않는다(20색이어도 5명이면 42%). 배정 규칙 자체가 **방 안에서의 유일성**을 보장하도록 바뀌어야 한다.

## What Changes

### front/ — 방 단위 닉네임 색 슬롯 배정

- `app/hooks/useRoomSubscription.ts` — 방 세션 동안 **playerId → 색 슬롯** 대응을 소유한다. 참가자를 처음 보는 순간(초기 방 상세의 멤버 목록, `JOINED` 이벤트, 아직 모르는 발신자의 `CHAT`) **가장 낮은 빈 슬롯**을 준다. `LEFT`로 떠난 참가자의 슬롯은 비워 다음 입장자가 재사용하되, **남아 있는 참가자의 슬롯은 세션 중 절대 바뀌지 않는다.** 방을 떠나면(구독 해제) 대응은 버린다
- `app/utils/ChatMessage.ts` — 채팅 메시지에 발신자의 색 슬롯 필드를 더한다. 슬롯은 메시지를 만드는 시점에 찍히므로 메시지 객체는 그대로 불변이고, `ChatMessageItem`의 `memo`는 유지된다
- `app/components/ui/ChatMessageList.tsx` — `senderId % 4` 규칙을 제거하고 메시지에 찍힌 슬롯으로 색 클래스를 고른다
- `app/app.css` — 채팅 슬롯 전용 색 토큰 20개(`--color-chat-0` ~ `--color-chat-19`)를 추가한다. 어두운 배경에서 지각 밝기·채도를 맞춘 색을 색상환에 18° 간격으로 놓고, **앞 슬롯일수록 이미 배정된 색과 멀도록** 순서를 정했다. 10명까지는 서로 36° 격자만큼(hex 실측 35° 이상) 떨어진 색만 쓰이고, 11명 이상인 드문 방에서만 비슷한 색이 섞이기 시작한다. 방 정원이 20이므로 슬롯이 부족한 경우는 없다
- 기존 네온 4색 토큰(`neon-cyan` 등)은 버튼·배지 등 다른 UI가 계속 쓰므로 그대로 둔다. 채팅 닉네임만 새 토큰으로 옮긴다
- 색 배정은 **각 클라이언트가 독립적으로** 한다. 같은 참가자가 뷰어마다 다른 색으로 보일 수 있으며, 이는 허용한다

### 범위 밖

- 같은 발신자의 연속 메시지 묶기 — 번갈아 말하는 경우의 문제를 풀지 못하므로 이 change에서 다루지 않는다
- 참가자 목록에 슬롯 색 표시
- 새로고침·재접속 후 색 유지 — 대응이 메모리에만 있으므로 뷰어 본인이 새로고침하면 색이 다시 배정된다
- 서버가 색을 배정해 모든 뷰어에게 같은 색을 보장하는 방식

### back/ · infra/ — 변경 없음

## Capabilities

### New Capabilities

- `room-chat-nickname-color`: 방 채팅 피드에서 참가자 닉네임 색을 방 단위로 배정해, 같은 방 안의 참가자끼리 색이 겹치지 않게 하고 세션 중 색이 바뀌지 않게 하는 규칙

### Modified Capabilities

- 없음.

## Impact

- **서브프로젝트**: `front/`만. `back/`·`infra/` 영향 없음
- **도메인 모듈**: 백엔드 모듈 변경 없음. 대응 화면은 `room` 도메인의 방 화면이다
- **헥사고날 계층**: 해당 없음(프론트 전용)
- **DB 스키마 / ES 매핑 / Kafka 토픽 / Redis 키**: 영향 없음
- **API·WebSocket 계약 변화**: 없음. 서버 이벤트(`JOINED`/`LEFT`/`CHAT`)와 방 상세 응답을 그대로 소비한다
- **외부 의존성**: 신규 npm 패키지 없음
- **영향 받는 화면**: `/rooms/:roomId`의 채팅 피드(대기·게임 중·정답 공개 구간 모두)
- **파일**:
  - 수정 — `app/hooks/useRoomSubscription.ts`, `app/utils/ChatMessage.ts`, `app/components/ui/ChatMessageList.tsx`, `app/app.css`
  - 손대지 않음 — `app/routes/RoomView.tsx`의 참가자 목록, `ChatInput.tsx`, 서버 코드
- **동작 변화**:
  - 같은 방의 참가자는 20명까지 서로 다른 닉네임 색을 받는다 **(주 수정)**
  - 누가 입장하거나 퇴장해도 이미 있던 참가자의 색은 바뀌지 않는다
  - 채팅 닉네임의 색이 기존 네온 4색에서 새 20색으로 바뀐다. 기존 cyan과 같은 색상이 슬롯 1에 남아 첫인상은 비슷하다
- **검증 제약**: 프론트에 테스트 프레임워크가 없으므로 자동 검증은 `npm run typecheck`·`npm run build`에 그친다. 유일성·안정성은 브라우저 여러 개로 한 방에 들어가 수동으로 확인한다
