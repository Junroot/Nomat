# Design Review Decisions

## 포기한 참가자의 정답 채팅이 OPEN 상태로 전원 방송되어 정답이 유출됨
- 심각도: [치명]
- 질문 요지: 포기자가 정답을 치면 판정에서 제외되어 REVEAL 전이가 일어나지 않고 정답 원문만 채팅에 방송된다. 방송 억제 / 포기자 정답도 전이 / 방송을 판정 뒤로 이동 / 현행 유지(위험 수용) 중 무엇을 택할지 물었다.
- 사용자 결정: 현행 유지 — 위험 수용
- 반영 방향: design.md 에 이 유출 경로를 **명시적으로 수용한 리스크**로 문서화한다. 다음을 담을 것 — (1) 경로 설명: 포기자가 정답 문자열을 치면 라운드가 OPEN 인 채 원문이 전원에게 방송되어 다른 참가자가 복사해 승점을 가져갈 수 있다, (2) 수용 근거: 파티 게임의 신뢰 전제(지인 기반 방)이며, 발생하려면 포기자가 정답을 알고 있으면서 채팅에 쳐야 하는 자발적 행위가 필요하다, (3) 대안을 택하지 않은 이유: 방송 억제는 Decision 8(포기 익명성)을 훼손하고, 포기자 정답의 라운드 전이는 Decision 4(포기의 대가)를 무의미하게 만들며, 방송을 판정 뒤로 옮기는 것은 proposal 이 범위 밖으로 분리한 기존 스펙-코드 divergence 를 이번 change 가 흡수하게 되어 tasks 8.2 와 충돌한다, (4) 후속: 필요하면 별도 change 로 방송/판정 순서 정리와 함께 재검토.
  Non-Goals 또는 Decisions 의 "수용한 리스크·스코프 아웃" 섹션에 적어, 다음 라운드의 독립 리뷰어가 "설계가 이미 의도적으로 다뤘다"고 인식하게 할 것.
- 상태: 반영완료
- 라운드: 1

## roundSeq가 게임마다 1로 되돌아가는데 passes·passSeq는 자연 종료 후에도 남아 유효성 계약이 거짓 양성이 된다
- 심각도: [치명]
- 질문 요지: 게임 자연 종료(ENDED) 시 teardown 이 호출되지 않아 `passes`/`passSeq` 가 24h TTL 로 남고, 재시작 시 `START_SCRIPT` 가 `roundSeq` 를 1 로 되돌리므로 이전 게임 1라운드의 포기가 새 게임 1라운드로 이월된다. 정리 책임을 (1) START_SCRIPT 에 DEL/HDEL 추가 (2) 자연 종료 경로에 teardown 추가 (3) passSeq 를 게임 단위로 유일화 중 어디에 둘지 물었다.
- 사용자 결정: START_SCRIPT 에 `DEL passes` + `HDEL passSeq` 추가
- 반영 방향: design.md 를 다음과 같이 고친다.
  1. Decision 5(lazy reset)의 유효성 계약에 **`roundSeq` 는 방 안에서 단조가 아니라 게임마다 1 로 되돌아간다**는 사실을 명시하고, 그래서 lazy reset 만으로는 게임 경계를 넘는 stale 이월을 막지 못한다는 한계를 적는다. lazy reset 은 **한 게임 안의 라운드 경계**를 담당하고, **게임 경계**는 START 시점의 명시적 삭제가 담당한다는 2단 구조로 계약을 다시 세운다.
  2. START_SCRIPT 를 수정 대상에 포함시키는 결정을 Decision 으로 세운다 — 게임 시작 시 `DEL <passes key>` 와 `HDEL <round hash> passSeq` 를 스크립트 안에서(기존 `HSET roundSeq 1` 과 같은 원자 실행 단위 안에서) 수행한다. 이로써 진입 시점에 포기 상태가 확정적으로 비어 있음이 보장된다.
  3. 기존에 "전이 스크립트는 수정하지 않는다"고 적힌 서술(Decision 5 의 채택 전제 포함)을 정정한다 — **START_SCRIPT 만 예외로 수정하며, 나머지 전이 스크립트(정답/타임아웃/다음 라운드 등)는 여전히 무수정**임을 명확히 구분해 적는다. 왜 START 만 예외인지(게임 경계는 lazy reset 이 원리적으로 감지할 수 없는 지점이기 때문) 근거를 남긴다.
  4. tasks.md 의 2.6 · 8.3 등 "전이 스크립트 무수정" 제약을 위 구분에 맞게 갱신하고, START_SCRIPT 수정 태스크와 검증 항목을 추가한다. 검증에는 **자연 종료 후 재시작 시나리오**(이전 게임 1라운드에서 포기 → 게임 종료 → 재시작 → 새 게임 1라운드에서 포기 상태가 비어 있고 정답 판정이 정상 동작) 회귀 테스트를 포함한다.
  5. delta spec 의 "이전 라운드의 포기를 이월당해서는 안 된다" 요구사항이 게임 경계에도 적용됨을 확인하고, 필요하면 게임 재시작 케이스를 시나리오로 명시한다.
- 상태: 반영완료
- 라운드: 2
