# 검증 사실 캐시

이 루프 실행 중 실제 코드를 열어 확인한 관찰 사실. 코드는 루프 중 불변이므로
같은 루프의 후속 에이전트는 이 관찰을 직접 확인한 것과 동등하게 신뢰해도 된다.
사실만 담는다 — 심각도·지적·권고·평가 금지.

- `RoundStateStoreImpl.kt:144-267 (companion object 전체)` — Lua 스크립트는 `START_SCRIPT`·`ADVANCE_ON_DEADLINE_SCRIPT`·`ADVANCE_ON_CORRECT_SCRIPT`·`FIND_DUE_SCRIPT`·`TEARDOWN_SCRIPT` 5개. `REVEAL_MILLIS = 5_000L`, `TTL_SECONDS = 86_400L`, `IGNORED_CODE = "0"`, `NOT_DUE_CODE = "-1"`, `NOW_MS`는 `redis.call('TIME')` 기반 ms epoch 조각 (라운드 1)
- `RoundStateStoreImpl.kt:223-247` — `ADVANCE_ON_CORRECT_SCRIPT`: `EXISTS` → `roundSeq` 비교 → `phase ~= 'OPEN'`이면 `'0'` → `now > deadline`이면 `'-1'` → `ZSCORE scores`가 있을 때만 `ZINCRBY` → `roundSeq+1`, `phase=REVEAL`, `deadlineAt=now+ARGV[4]`, `ZADD deadlines`. 반환 `'1|REVEAL|<newSeq>|<trackIndex>|<revealDeadline>|<winnerId>'` (라운드 1)
- `RoundStateStoreImpl.kt:180-221` — `ADVANCE_ON_DEADLINE_SCRIPT`는 `OPEN→REVEAL`, `REVEAL→OPEN/ENDED` 전이를 수행하며 `passes` 유사 키를 전혀 건드리지 않는다. `START_SCRIPT`(155-178)·`TEARDOWN_SCRIPT`(258-266)도 마찬가지로 `passes` 키 개념이 없다 (라운드 1)
- `RoundStateStoreImpl.kt:258-266` — `TEARDOWN_SCRIPT`는 KEYS[1]=round `DEL`, KEYS[2]=deadlines `ZREM`, KEYS[3]=scores `DEL` (라운드 1)
- `RoundStateStoreImpl.kt:73-91` — `snapshot(roomId: Long)`은 round Hash 전체를 `entries`로 읽고 `scoreboard(roomId)`를 덧붙인다. playerId 파라미터 없음 (라운드 1)
- `RoundStateStoreImpl.kt:114-116` — `removeScore(roomId, playerId)`는 `ZREM scores <playerId>` 단독 호출(Lua 아님) (라운드 1)
- `RoundStateStore.kt:9-37` — 포트 메서드는 `start`·`tryAdvanceOnDeadline`·`tryAdvanceOnCorrect`·`snapshot(roomId)`·`findDueRoomIds`·`scoreboard`·`removeScore`·`teardown`. 포기 관련 메서드 없음 (라운드 1)
- `RoundService.kt:66-80` — `submitAnswer(roomId, playerId, content)`는 `snapshot(roomId)` → `phase != OPEN`이면 return → 트랙 조회 → `AnswerMatcher.matches` → `tryAdvanceOnCorrect` → TRANSITIONED면 `publishRoundRevealed` (라운드 1)
- `RoundService.kt:94-97` — `onPlayerLeft(roomId, playerId)`의 현재 본문은 `roundStateStore.removeScore(roomId, playerId)` 한 줄 (라운드 1)
