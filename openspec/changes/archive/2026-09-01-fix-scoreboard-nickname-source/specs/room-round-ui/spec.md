## MODIFIED Requirements

### Requirement: ROUND_REVEALED 수신 시 정답·승자·점수판을 표시한다

시스템은 `ROUND_REVEALED`를 받으면 정규 정답(`title`)·승자(`winnerId`)·갱신된 점수판(`scores`)을 표시해야(SHALL) 한다. 승자가 없으면(`winnerId=null`, 타임아웃) 정답과 함께 시간 초과로 표시한다.

점수판 항목과 승자 이름은 **서버가 해석해 보낸 닉네임**(`scores[].nickname`·`winnerNickname`)을 그대로 표기해야(SHALL) 하며, 방의 현재 멤버 목록(`players`)과 조인해서는 안 된다(SHALL NOT). 멤버 목록은 퇴장 즉시 줄어드는 반면 점수판은 다음 공개까지(종료 후에는 영구히) 유지되므로, 둘을 조인하면 **이미 떠난 참가자의 이름이 사라진다.** `nickname`을 해석할 수 없는 경우에만 중립 라벨로 대체하며, 퇴장을 단정하는 표기는 쓰지 않는다.

정답 공개 구간에는 **정답 곡을 클립 시작 지점부터 다시 재생해야(SHALL) 한다.** 이전 요구사항은 이 시점에 "클립을 정지"하도록 규정했으나, 그러면 참가자가 정답을 텍스트로만 확인하고 **곡을 듣지 못한 채** 다음 라운드로 넘어간다. 특히 타임아웃으로 공개된 라운드는 클립이 이미 소진돼 있어(`openDuration = 클립 길이 × repeatCount + 여유`) 정지 여부와 무관하게 무음이 된다 — 아무도 맞히지 못한 곡일수록 들려줄 필요가 큰데 정확히 그 경우에 들리지 않았다.

이 재생은 다음 라운드 선버퍼링과 **동시에 성립해야(SHALL) 한다.** 선버퍼링은 다음 곡을 실제로 적재해 버퍼를 채우는 방식이라 하나의 플레이어로는 현재 곡 재생과 양립할 수 없다. 구현 방식은 `add-room-round-frontend`·`reduce-round-playback-latency`의 `design.md` Decision 4를 따른다.

정답 공개 구간에는 **정답 곡의 영상을 화면에 표시해야(SHALL) 한다.** 다만 노출 범위는 엄격히 제한된다:

- `OPEN` 동안에는 영상을 **표시해서는 안 된다(SHALL NOT)** — 썸네일과 영상 제목이 곧 정답이므로 표시하면 게임이 성립하지 않는다
- 선버퍼링 중인 플레이어의 영상도 **표시해서는 안 된다(SHALL NOT)** — 다음 라운드의 곡을 물고 있어 표시하면 다음 정답이 유출된다

즉 표시 대상은 **정답 공개 구간의 재생 담당 플레이어 하나뿐**이다.

#### Scenario: 승자가 있으면 정답과 승자를 표시한다
- **WHEN** `type=ROUND_REVEALED`를 수신(`winnerId` 존재)
- **THEN** 정답(`title`)과 서버가 보낸 승자 닉네임(`winnerNickname`), 갱신된 점수판이 표시되어야 한다

#### Scenario: 승자가 공개 직후 퇴장해도 승자 이름이 유지된다
- **WHEN** `ROUND_REVEALED` 표시 중 승자가 방을 떠나 `type=LEFT`가 도착
- **THEN** 승자 이름이 계속 표시되어야 한다 (멤버 목록 변화가 이미 받은 공개 정보를 바꾸지 않는다)

#### Scenario: 타임아웃이면 정답과 시간 초과를 표시한다
- **WHEN** `type=ROUND_REVEALED`를 수신하고 `winnerId`가 null
- **THEN** 정답과 함께 아무도 맞히지 못했음이 표시되어야 한다

#### Scenario: 정답 공개 구간에 정답 곡이 들린다
- **WHEN** 라운드가 `REVEAL`로 전이됨
- **THEN** 정답 곡이 클립 시작 지점부터 다시 재생되어야 한다
- **AND** 아무도 맞히지 못해 클립이 이미 소진된 라운드에서도 들려야 한다
- **AND** 같은 구간에 다음 라운드 트랙의 선버퍼링이 함께 진행되어야 한다

#### Scenario: 정답 공개 구간에만 영상이 보인다
- **WHEN** 라운드가 `REVEAL`로 전이됨
- **THEN** 정답 곡의 영상이 정답·승자 정보와 함께 화면에 표시되어야 한다
- **AND** 선버퍼링 중인 다음 곡의 영상은 표시되지 않아야 한다

#### Scenario: OPEN 중에는 영상이 보이지 않는다
- **WHEN** 라운드가 `OPEN`이고 클립이 재생 중임
- **THEN** 영상이 화면에 표시되지 않아야 한다 (썸네일·제목이 정답을 노출하므로)

### Requirement: 게임 종료 시 마지막 점수로 최종 결과 화면을 보여준다

시스템은 `ENDED`를 받으면 게임 종료로 처리하고, 직전 `ROUND_REVEALED`가 전달한 마지막 점수판(sticky 보존)으로 **최종 결과(순위) 화면**을 표시해야(SHALL) 한다. `ENDED` 메시지에는 점수판이 실리지 않으므로 프론트가 마지막 `scores`를 유지해 사용한다. `ENDED`는 행위자 유무(방장 수동 종료 vs 서버 주도 자연 종료)와 무관하게 게임 종료로 처리한다. 종료 후 방 상태는 `ACTIVE`로 복귀한다.

이 sticky 점수판은 **자기완결적이어야(SHALL) 한다** — 순위·닉네임·점수를 그리는 데 필요한 정보를 점수판 바깥(현재 멤버 목록 등)에서 찾지 않는다. 결과 화면은 게임이 끝난 시점의 기록이므로, **그 이후의 입·퇴장으로 표시 내용이 달라져서는 안 된다(SHALL NOT).**

#### Scenario: 게임이 끝나면 최종 순위가 표시된다
- **WHEN** `type=ENDED`를 수신
- **THEN** 마지막 `ROUND_REVEALED`의 점수판으로 순위(닉네임·점수)와 우승자 하이라이트가 표시되어야 한다
- **AND** 방 상태가 `ACTIVE`로 복귀해 로비로 돌아갈 수 있어야 한다

#### Scenario: 결과 화면이 뜬 뒤 퇴장한 참가자도 이름으로 표시된다
- **WHEN** 최종 결과 화면 표시 중 다른 참가자가 방을 떠나 `type=LEFT`가 도착
- **THEN** 그 참가자의 순위·닉네임·점수가 변하지 않고 그대로 표시되어야 한다
- **AND** 닉네임이 `(퇴장)` 같은 대체 문구로 바뀌지 않아야 한다

#### Scenario: 서버 주도 종료도 행위자 없이 결과를 보여준다
- **WHEN** 라운드 엔진이 서버 주도로 종료해 행위자(`playerId`/`nickname`) 없는 `ENDED`가 도착
- **THEN** 행위자 유무와 무관하게 최종 결과 화면이 표시되어야 한다
