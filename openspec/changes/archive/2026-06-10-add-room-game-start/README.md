# add-room-game-start

방장이 ACTIVE 상태의 방에서 "게임 시작"을 트리거하면 방이 `PLAYING` 상태로 전이되고, 그 전이가 기존 room 실시간 백본(도메인 이벤트 → Redis pub/sub → STOMP fan-out)을 그대로 재사용해 모든 참가자에게 브로드캐스트된다. `PLAYING` 동안에는 **신규 입장이 거부**되되(중간 입장 금지), 끊겼다 돌아오는 기존 멤버의 **재접속(유예 시간 내)은 그대로 허용**된다 — 입장 차단의 집행점을 `Room.join()` 도메인 가드 한 곳에 두어, 재접속 경로(`cancelGracePeriod`)가 `join()`을 우회한다는 기존 구조를 활용한 결과다. 슬라이스를 닫기 위해 방장이 게임을 끝내 다시 입장 가능한 `ACTIVE`로 되돌리는 최소 종료 전이도 포함한다.

라운드 진행·오디오 동기화·정답 매칭·점수 계산은 본 변경의 범위가 아니다(후속 "라운드 엔진" 변경). 본 변경은 새 도메인 모듈 없이 기존 `room` 모듈 위에 게임 세션 상태 전이와 입장 게이팅만 얹는 워킹 스켈레톤이다.
