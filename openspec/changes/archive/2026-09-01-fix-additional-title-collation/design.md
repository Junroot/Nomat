## Context

추가 정답(`Track.additionalTitles`)은 JVM에서 `Set<String>`이고, 저장은 `@ElementCollection`이 `track_additional_title`로 푼다. 이 컬렉션 테이블의 PK `(track_id, additional_title)`는 손으로 작성한 마이그레이션이 정한 것이고, 컬럼 콜레이션은 테이블 기본값 `utf8mb4_unicode_ci`를 그대로 물려받았다.

즉 **"두 추가 정답이 같은가"를 판정하는 규칙을 아무도 의식적으로 정하지 않았고**, 테이블 생성 시 관례적으로 붙인 콜레이션이 그 자리를 채웠다. 그 규칙이 UCA primary weight 비교라서, 일본어 표기 흔들림을 전부 동일시한다.

관용도 스펙트럼에서 각 관문의 위치:

```
   엄격 ◀────────────────────────────────────────────────▶ 관용

   코드포인트 일치        (비어 있음)            utf8mb4_unicode_ci
   ├ 프론트 중복 검사                            ├ 탁점 무시  ハ=バ=パ
   ├ JVM Set<String>                             ├ 가나 종류 무시
   └ AnswerMatcher                               └ 전각/반각 무시
        │                                              │
        └──────── 앱 전체가 여기 ──────┐   ┌── DB 혼자 여기 ──┘
                                       ✗ 불일치 = 500
```

앱은 스펙트럼의 한쪽 끝, DB는 반대쪽 끝에 있다. 둘 사이 어딘가가 아니라 **정반대**라는 점이 이 문제의 성격이다.

## Goals / Non-Goals

**Goals**

- 정당한 추가 정답 조합이 저장 단계에서 거부되지 않게 한다
- 유일성 판정의 주체를 명시적으로 정한다 — 콜레이션이 우연히 정하는 상태를 끝낸다
- 코드 변경 없이, 배포 가능한 최소 단위로 장애를 멈춘다

**Non-Goals**

- 정답 매칭 규칙 변경 — 후속 change `normalize-answer-matching`의 범위다
- 추가 정답 등록 UX 개선 — 같은 후속 change
- `track.title`·`room_playlist_track.title` 등 유일성 제약이 없는 다른 `_ci` 컬럼 — 제약이 없으므로 장애를 일으키지 않는다. 애플리케이션이 DB 문자열 비교에 의존하는 지점이 없어 그대로 둔다

## Decision 1: 콜레이션을 `utf8mb4_0900_bin`으로 바꾼다

**결정**: 두 `additional_title` 컬럼을 `utf8mb4_0900_bin`으로 변경한다.

| 안 | 장애 해결 | 정당한 입력 허용 | 비용 | 판정 |
|---|---|---|---|---|
| **A. 콜레이션 변경** | ✅ 완전 | ✅ | 마이그레이션 1개, 코드 0 | ✅ **채택** |
| B. 문자열을 PK에서 제거 (대리키/무PK) | ✅ 완전 | ✅ | 마이그레이션 + 엔티티 매핑 변경 | 기각 |
| C. 요청 단계에서 정규화·중복 제거 | ❌ **불충분** | — | 작음 | 기각 |
| D. `DataIntegrityViolationException` → 400 | ⚠️ 은폐만 | ❌ | 작음 | 기각 |

**C가 왜 불충분한가**: 어떤 정규화를 넣더라도 `unicode_ci`가 접는 축(특히 탁점 `ハ`/`バ`)을 전부 따라 접지 않는 한 충돌은 남는다. 그리고 탁점을 접는 것은 **정답 판정으로서 틀렸다** — `かっこう`(뻐꾸기)와 `がっこう`(학교)는 다른 단어다. 즉 C만으로는 원리적으로 막을 수 없다.

**D가 왜 부족한가**: 500이 400으로 바뀔 뿐, 사용자는 여전히 정당한 플레이리스트를 저장하지 못한다. 게다가 거부 사유를 설명할 방법이 없다 — 사용자 눈에는 명백히 다른 글자다.

**B가 아니라 A인 이유**: 도메인 타입이 `Set<String>`인 이상 DB는 그 동치를 그대로 표현하는 것이 맞다. B는 제약을 없애 증상을 피하는 쪽이고, A는 제약의 기준을 바로잡는 쪽이다. A를 택하면 제약은 **도메인 규칙이 깨졌을 때만 울리는 경보**로 남는다.

**`utf8mb4_bin`이 아니라 `utf8mb4_0900_bin`인 이유**: 전자는 PAD SPACE라 후행 공백을 무시해(`"마이" = "마이 "`) JVM `String.equals`와 어긋난다. 후자는 NO PAD여서 정확히 일치한다. MySQL 8.0.39(`ContainerConfiguration.kt:20`, `infra/data/compose.yml`)를 쓰고 있어 사용 가능하다.

## Decision 2: 선행 데이터 정리는 필요 없다

콜레이션을 촘촘하게 바꾸는 ALTER는 기존 데이터에서 PK 충돌을 만들 수 없다.

```
   현재 PK가 성립한다
        ⟹  모든 행이 ci(거친 기준)에서 서로 다르다
        ⟹  더 촘촘한 bin 기준에서도 당연히 서로 다르다
        ⟹  ALTER 후에도 PK 위반은 발생할 수 없다   ✅
```

거친 동치에서 구별되던 값은 더 촘촘한 동치에서도 구별된다. 따라서 중복 행 사전 조회·정리 없이 바로 ALTER할 수 있다. (반대 방향, 즉 bin → ci로 되돌리는 ALTER는 이 논증이 성립하지 않는다 — Decision 3.)

## Decision 3: 배포 영향과 롤백 — 롤백 창은 시간이 지나면 닫힌다

**Flyway 버전**: `V11__change_additional_title_collation.sql` (현재 최신은 `V10__create_event_publication.sql`)

**무중단 배포 영향**: MySQL 8.0에서 컬럼 콜레이션 변경은 INPLACE로 처리되지 않아 테이블 복사(`ALGORITHM=COPY`)로 수행된다. 두 컬럼 모두 PK 구성 요소라 PK 인덱스도 함께 재구축된다. 복사 중에는 읽기는 가능하지만 **쓰기가 차단**된다. 대상은 추가 정답 행뿐이라 규모가 작을 것으로 보이나, 배포 전에 실제 행 수를 확인해 차단 시간을 가늠한다(tasks 1.1).

애플리케이션 재시작은 필요 없다. 스키마의 논리 구조(컬럼·타입·제약)가 그대로여서 Hibernate 매핑과 기존 인스턴스 모두 영향을 받지 않는다.

**롤백**: 역방향 ALTER(`utf8mb4_0900_bin` → `utf8mb4_unicode_ci`)로 되돌릴 수 있으나, **되돌릴 수 있는 기간이 제한된다.**

```
   배포 직후          시간 경과
      │                  │
      │   사용자가 ウェイ + ウエイ 를 등록  (bin 에서는 정상)
      ▼                  ▼
   롤백 가능        롤백 시 ci 기준 중복 발생 → 역방향 ALTER 실패
```

bin 상태에서 새로 저장된 행 중 ci 기준으로 충돌하는 쌍이 하나라도 생기면 역방향 ALTER가 거부된다. 즉 **롤백은 "아직 아무도 그런 조합을 등록하지 않았을 때"만 가능**하고, 그 조합이야말로 이 변경이 허용하려는 바로 그 데이터다. 되돌리려면 그 행들을 먼저 삭제해야 하고, 그것은 사용자 데이터 손실이다.

이 비대칭은 감수한다. 되돌릴 이유가 생길 만한 위험 요소가 없기 때문이다 — 코드 변경이 없고, 제약이 느슨해지는 방향이라 기존 동작 중 깨질 것이 없다.

## 검증 방법

프론트에 테스트 프레임워크가 없고 본 변경은 백엔드 전용이므로, 기존 `@IntegrationTest` + Testcontainers 패턴으로 검증한다. 핵심은 **콜레이션이 실제로 바뀌었는지가 아니라, 지금까지 거부되던 요청이 통과하는지**다.

- `PlaylistControllerTest` 패턴을 따라, 탁점만 다른 두 추가 정답(`ハハ`/`ババ`)을 가진 플레이리스트 저장이 성공하는지
- 같은 플레이리스트로 방을 만들 때 `room_track_additional_title` 복사도 성공하는지 — 두 테이블을 함께 옮겼는지 확인하는 유일한 경로다
- 완전히 동일한 문자열은 여전히 하나로만 저장되는지 (`Set` 의미 보존)
