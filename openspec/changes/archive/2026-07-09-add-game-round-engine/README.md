# add-game-round-engine

`RoomStatus.PLAYING`이라는 빈 우산 안을 채우는 **라운드 엔진**이다. 선행 변경 `add-room-game-start`가 게임 세션 상태 전이(`ACTIVE ↔ PLAYING`)와 입장 게이팅만 깔아두고 "라운드·정답·점수는 후속 라운드 엔진" "종료는 서버 주도로 확장"이라고 명시적으로 미뤄둔 그 후속이다.

게임은 플레이리스트의 **모든 트랙을 한 라운드씩** 돈다. 라운드마다 클립을 재생하고, 참가자는 채팅으로 정답을 입력한다. **첫 정답자만 1점**을 얻고, 라운드는 **첫 정답 또는 클립이 `repeatCount`회 재생 완료**(타임아웃) 중 먼저로 끝난다. 정답을 5초간 공개(REVEAL)한 뒤 곧장 다음 라운드(`ROUND_OPEN`)로 넘어가고, 마지막 트랙이 끝나면 누적 점수 최고자를 우승으로 게임이 종료되어 방이 다시 `ACTIVE` 로비로 복귀한다.

라운드 전이는 **서버가 시계의 주인**이다. 다중 인스턴스(Swarm replica 2)·인스턴스 장애에서도 정확히 한 번만 전이되도록, 진실은 Redis 키의 단일 원자 Lua CAS(epoch+phase 게이트)에 두고, 타임아웃·정답 공개 전이는 ShedLock으로 단일 replica만 도는 `@Scheduled` sweeper(약 1초 폴링)가 구동한다. 정밀이 필요한 첫 정답은 타이머가 아니라 들어온 채팅 메시지로 즉시 처리되므로(이벤트 구동), 폴링의 ~1초 지터는 정밀이 필요 없는 타임아웃·공개 전이에만 영향을 준다. 신규 외부 의존성·인프라 변경은 없다(Redisson·Quartz·keyspace 알림·replica별 로컬 타이머 모두 불채택, 기존 패턴 복제).

정답은 OPEN 동안 클라이언트에 절대 내려가지 않으며(answer-stripped), 재접속 시 서버가 정답을 뺀 라운드 스냅샷을 제공한다. 게임 중 퇴장한 플레이어는 점수판에서 제거된다.

본 변경은 **백엔드 라운드 엔진과 실시간 프로토콜**(이벤트·answer-stripped 스냅샷·채팅 정답 판정·점수)까지만 다룬다. **프론트엔드**(방 화면 오디오 재생·라운드 UI·결과 화면·재접속 화면 복원)와 **"버퍼 완료 후 동시 시작"**(클라이언트 간 재생 동기화)은 본 변경 범위가 아니며 후속 변경으로 분리한다. 검증은 STOMP 통합 테스트로 한다.
