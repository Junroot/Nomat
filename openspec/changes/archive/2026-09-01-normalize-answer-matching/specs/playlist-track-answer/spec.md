## ADDED Requirements

### Requirement: 추가 정답은 표기 정규화 기준으로 중복 등록되지 않는다

시스템은 한 트랙의 추가 정답 목록에서 **표기 정규화 후 같은 값이 되는 두 항목을 함께 보관하지 않아야(SHALL NOT)** 한다. 중복 판정에 쓰는 정규화 규칙은 정답 매칭에 쓰는 규칙과 **동일한 하나**여야 한다.

정규화는 다음 축을 접고, 나머지는 접지 않는다.

- 접음: 전각/반각, 히라가나/가타카나, 큰 가나/작은 가나, 대소문자, 공백·구두점·기호
- 접지 않음: 탁점·반탁점, 장음 부호, 괄호 안의 내용

> 두 규칙이 같아야 하는 이유: 두 추가 정답이 매칭상 구분 불가하면 플레이어가 무엇을 입력하든 같은 판정을 내므로, 둘 다 보관해서 얻는 것이 없다. 중복 판정만 보수적으로 두면 아무 효과 없는 항목이 추가 정답 예산(최대 10개)을 잠식한다.

중복이 발견되면 시스템은 요청을 **거부하지 않고 먼저 등록된 값을 남긴 채 이후 항목을 버려야(SHALL)** 한다. 거부하면, 이 규칙이 도입되기 전에 저장된 항목을 가진 플레이리스트가 편집 불가 상태로 잠긴다.

#### Scenario: 가나 표기만 다른 추가 정답은 하나만 보관된다
- **WHEN** 한 트랙의 추가 정답으로 `マイウェイ`와 `まいうぇい`를 함께 담아 플레이리스트 생성을 요청
- **THEN** MySQL의 `track_additional_title`에 먼저 온 `マイウェイ`만 저장되어야 한다
- **AND** 요청은 성공해야 한다

#### Scenario: 구두점만 다른 추가 정답은 하나만 보관된다
- **WHEN** 한 트랙의 추가 정답으로 `マイ・ウェイ`와 `マイウェイ`를 함께 담아 요청
- **THEN** MySQL의 `track_additional_title`에 둘 중 하나만 저장되고 요청은 성공해야 한다

#### Scenario: 탁점이 다른 추가 정답은 둘 다 보관된다
- **WHEN** 한 트랙의 추가 정답으로 `ハハ`와 `ババ`를 함께 담아 요청
- **THEN** MySQL의 `track_additional_title`에 두 값이 모두 저장되어야 한다

#### Scenario: 괄호 꼬리표가 다른 추가 정답은 둘 다 보관된다
- **WHEN** 한 트랙의 추가 정답으로 `Monster`와 `Monster (feat. X)`를 함께 담아 요청
- **THEN** MySQL의 `track_additional_title`에 두 값이 모두 저장되어야 한다

#### Scenario: 레거시 중복이 있는 플레이리스트도 수정할 수 있다
- **WHEN** 규칙 도입 이전에 저장되어 정규화 기준으로 중복인 추가 정답을 가진 플레이리스트를 수정 요청
- **THEN** 요청이 거부되지 않고 중복이 접힌 상태로 저장되어야 한다

### Requirement: 추가 정답은 입력 원문 그대로 저장된다

시스템은 추가 정답을 **사용자가 입력한 문자열 그대로** 저장해야(SHALL) 하며, 정규화된 형태로 변환해 저장해서는 안 된다(MUST NOT). 정규화는 비교 시점에만 적용한다.

> 원문을 보존해야 하는 이유: 저장된 값은 플레이리스트 편집 화면으로 그대로 내려간다. 히라가나로 입력한 값을 가타카나로 바꿔 돌려주면 사용자는 자기가 입력한 것을 잃는다. 또한 정규화 규칙이 나중에 바뀌어도 재마이그레이션이 필요 없다.

#### Scenario: 히라가나로 입력한 추가 정답이 히라가나로 조회된다
- **WHEN** 추가 정답 `まいうぇい`를 등록한 뒤 플레이리스트를 조회
- **THEN** 응답의 추가 정답이 `まいうぇい`여야 한다 (가타카나로 변환되지 않는다)

#### Scenario: 구두점이 포함된 추가 정답이 그대로 조회된다
- **WHEN** 추가 정답 `밤을 달리다!`를 등록한 뒤 플레이리스트를 조회
- **THEN** 응답의 추가 정답이 공백과 `!`를 포함한 `밤을 달리다!`여야 한다

### Requirement: 추가 정답 입력 화면은 이미 인정되는 값의 추가를 사전에 차단하고 이유를 알린다

플레이리스트 편집 화면은 새 추가 정답이 이미 등록된 항목과 정규화 기준으로 같으면 **목록에 추가하지 않아야(SHALL NOT)** 하며, 그 사실을 사용자에게 **알려야(SHALL)** 한다. 판정 규칙은 서버와 동일하다.

> 알림이 필요한 이유: 사용자 눈에 `マイウェイ`와 `マイ・ウェイ`는 명백히 다른 글자다. 아무 반응 없이 무시되면 입력이 먹히지 않는 버그로 보인다. 안내는 "중복이라 거부됨"이 아니라 "이미 정답으로 인정되므로 등록할 필요가 없음"으로 읽혀야 한다.

#### Scenario: 표기만 다른 값을 추가하면 안내가 표시된다
- **WHEN** `マイウェイ`가 등록된 상태에서 사용자가 `マイ・ウェイ`를 입력하고 엔터를 누름
- **THEN** 목록에 추가되지 않아야 한다
- **AND** 이미 정답으로 인정된다는 안내가 표시되어야 한다

#### Scenario: 탁점이 다른 값은 정상적으로 추가된다
- **WHEN** `ハハ`가 등록된 상태에서 사용자가 `ババ`를 입력하고 엔터를 누름
- **THEN** 목록에 추가되어야 한다
